# English Step — развёртывание через GitHub → BotHost

Версия подготовлена для BotHost: **один контейнер Node.js 24**, встроенный веб-сервер на внутреннем порту **3000**, обратный HTTPS-прокси от BotHost, постоянный SQLite в `/app/data`. Никакого отдельного Caddy / Docker Compose на BotHost запускать не требуется.

## 1. Загрузка на GitHub

Распакуйте этот ZIP и загрузите **содержимое ZIP в корень репозитория** — `server.mjs`, `Dockerfile`, `package.json`, папки `public/`, `lib/`, `scripts/` должны лежать непосредственно в корне GitHub-репозитория, не внутри дополнительной `english-step-selfhost/` папки. Не загружайте `.env`, файлы SQLite, папку `data` или личные данные. Исходные PDF учебников в приложение не входят.

## 2. Создайте приложение на BotHost

1. Откройте https://bothost.ru/dashboard.php и создайте проект с исходниками из репозитория GitHub (`main` или ваша фактическая ветка).
2. В дополнительных настройках выберите **«Использовать собственный Dockerfile»**. Внутренний **порт 3000**, веб-домен включён (поддомен BotHost или свой домен).
3. Выделите домен/поддомен, после чего используйте его точный HTTPS-адрес в `PUBLIC_URL` (например `https://english-test.bothost.tech`; пример нельзя копировать без замены). Порт 3000 не вписывается в публичный URL.
4. `BOT_TOKEN` самому сайту English Step **не нужен**; если интерфейс BotHost требует его как обязательное поле, не придумывайте фейковый токен: используйте доступный режим веб-приложения или уточните у поддержки BotHost.

## 3. Настройка логина (секреты — НЕ в GitHub)

На своём компьютере, в папке проекта с установленным Node.js (лучше 24-й версии), запустите:

```bash
node scripts/bothost-credentials.mjs
```

Скрипт спросит точный URL вида `https://<ВАШ_ДОМЕН>` и логин, создаст случайный пароль, рассчитает scrypt-хеш. Он выведет значения `PUBLIC_URL`, `ADMIN_LOGIN`, `ADMIN_PASSWORD_HASH`, `DATA_DIR`. **Пароль сохраните лично**. Хеш и другие значения заполните в настройках **переменных окружения BotHost**. Не добавляйте `.env` в GitHub! Пароль тоже нельзя добавлять в GitHub. Порт настройте в панели как `3000`; BotHost передаст `PORT` приложению автоматически.

> Если URL ещё неизвестен, сначала создайте веб-проект и выберите домен, затем установите переменные и выполните новый деплой. При каждом изменении публичного URL обновляйте `PUBLIC_URL` в настройках.

## 4. Деплой и проверка

Запустите деплой в панели BotHost, затем проверьте runtime-логи. В идеале увидите `English Step listening on port 3000`. По адресу `https://<ВАШ_ДОМЕН>/healthz` для неавторизованного посетителя должен отобразиться `{"ok":true}`. Откройте главную страницу — она перенаправит на страницу входа. Войдите с логином и паролем из скрипта. Проверьте все три ступени, упражнения и сохранение прогресса после обновления страницы.

Если ошибка 502/504: убедитесь, что в настройках BotHost проксируется порт **3000**, собственный Dockerfile включён, в логах нет ошибок запуска, а домен включён.

Если в логах `Set ADMIN_LOGIN and ADMIN_PASSWORD_HASH...`, проверьте переменные. Если ошибка `Use HTTPS for a public server` или вход блокируется по origin — проверьте `PUBLIC_URL` (должен ТОЧНО совпадать с адресом в браузере, без последнего `/`). Если база не создаётся — проверьте право записи в `/app/data` и настройки постоянного хранилища BotHost.

## 5. Прогресс и обновления

SQLite находится по `/app/data/english-step.sqlite`, в рекомендуемом BotHost персистентном каталоге. После изменения GitHub репозитория делайте деплой. Папку `/app/data` и БД нельзя удалять. Резервное копирование: экспорт JSON в «Настройки → Экспорт» и/или резервная копия из панели/терминала BotHost. Для переноса старых результатов применяйте JSON «Настройки → Импорт», предварительно экспортированный из прежней версии.

Приложение рассчитано на **один аккаунт владельца** для синхронизации между ПК и телефоном. Регистрации независимых учеников в данном проекте нет.
