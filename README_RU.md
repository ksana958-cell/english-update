# English Step — установка на свой сервер

Это самостоятельная версия сайта: 109 уроков в трёх ступенях, 627 заданий, 436 слов и выражений, 40 учебных примеров по мотивам кино и комиксов, 24 фильма по уровням A1–C2, озвучка, повторения и серверное сохранение прогресса. Она не использует ChatGPT для входа или Cloudflare D1 для хранения данных.


## Обновление: три учебные ступени

Теперь в разделе **«Мой курс»** можно выбрать одну из трёх ступеней:

1. **Grammarway 1 (A1–A2)** — прежние 20 уроков (162 задания и 80 слов). Ничего не удалено, старые ID, заметки, XP и расписание повторения совместимы с новой версией.
2. **English File (Fifth Edition) — Intermediate, Oxford University Press (примерно B1–B1+)** — 20 новых уроков 1A–10B, 120 авторских заданий, 80 слов, 20 коротких текстов для чтения. Тематическая структура следует содержанию предоставленного Student Book; это НЕ начинающий уровень Beginner.
3. **English for Everyone, Level 4 Advanced, DK (примерно B2–C1)** — 69 новых модулей, 345 авторских заданий и 276 слов/выражений. Сохранён порядок грамматических и словарных блоков оригинальной книги.

**Всего:** 109 уроков, 627 заданий, 436 карточек слов. Уровни CEFR ориентировочные: это не результат тестирования и не официальный сертификат. Новый раздел прогресса показывает результаты по выбранной ступени, а серверная синхронизация сохраняет их в одном аккаунте. Словарь показывает слова текущей ступени; все упражнения доступны из учебных карточек.

**Установка поверх предыдущей версии:** сначала сделать экспорт/резервную копию, сохранить `.env` и Docker-том `progress`, затем заменить файлы исходников и выполнить `docker compose up -d --build`. Не выполнять `docker compose down -v`. Существующий пароль и результаты сохраняются. Для сохранения результатов новых уроков необходимо обновить **и frontend, и backend** (`public/progress-core.mjs`, `server.mjs`, `lib/progress-service.mjs`); замена только JSON-файлов неполная.

Загруженные PDF учебников в публичную раздачу сайта не включены. Сайт не дублирует страницы или авторские упражнения издателей: по их структуре создана отдельная учебная программа с оригинальными формулировками, мини-текстами и проверками. Аудио уроков синтезируется голосами браузера, а не берётся из записей Oxford/DK. Для изучения оригинальных книжных упражнений используй законно полученные экземпляры учебников и официальные аудиоматериалы.

Более подробная карта тем и обоснование интеграции находятся в `АНАЛИЗ_И_КАРТА_КУРСОВ.md`.

## Что понадобится

- VPS с Linux, Docker Engine и Docker Compose v2. Для личного использования разумный начальный ориентир — 1 CPU, 512 МБ–1 ГБ памяти и место для резервных копий.
- Домен или поддомен, например `english.example.com`, с A-записью на IP сервера. Если есть AAAA-запись, она тоже должна вести на этот сервер.
- Открытые входящие TCP-порты 80 и 443. UDP 443 необязателен. Эти порты не должны быть заняты другим веб-сервером.

Подойдут VPS или платформа, умеющая запускать Docker/Node.js с постоянным диском. Обычный хостинг только для PHP, GitHub Pages и чисто статический хостинг для этой версии не подходят.

Архив рассчитан на одного владельца. На всех устройствах используется один логин и пароль. Самостоятельная регистрация других пользователей не предусмотрена.

## 1. Распаковать архив

Загрузи архив на сервер через SFTP и распакуй. Перейди в папку, где находятся `Dockerfile` и `compose.yaml`:

```bash
unzip english-step-selfhost.zip
cd english-step-selfhost
```

Если Docker ещё не установлен, используй официальную инструкцию для своей системы: https://docs.docker.com/engine/install/ . Не устанавливай Node.js отдельно, если запускаешь всё через Docker.

## 2. Создать настройки и пароль

Из папки проекта запусти:

```bash
docker run --rm -it --user "$(id -u):$(id -g)" -v "$PWD:/app" -w /app node:24-alpine node scripts/configure.mjs
```

Скрипт спросит:

1. Адрес сайта — полный адрес вида `https://english.example.com`, без дополнительного пути.
2. Логин — можно оставить `gleb`.

Затем он создаст `.env` и покажет случайный пароль. Сохрани пароль в менеджере паролей. В `.env` записывается только хеш пароля. Файл `.env` уже настроен для исключения из Git и Docker-образа.

Не запускай скрипт повторно для обычного перезапуска: сохранённые настройки уже готовы. Файл `.env.example` — только справочный образец; напрямую запускать его нельзя.

## 3. Запустить

```bash
docker compose up -d --build
docker compose ps
```

Открой свой адрес сайта. Caddy автоматически получит HTTPS-сертификат, когда домен указывает на сервер и доступны порты 80/443. Первый выпуск сертификата может занять некоторое время.

Войди с созданными логином и паролем. На телефоне и компьютере используй те же данные. Перед переходом на другое устройство дождись отметки «Сохранено в аккаунте».

Проверка работы:

```bash
docker compose logs --tail=100 app caddy
```

Приложение запускается автоматически после перезапуска Docker. Если Docker не запускается при старте VPS, включи его автозапуск средствами своей системы.

## 4. Перенести прогресс с прежнего сайта

Автоматического доступа к прежней базе у нового сервера нет. Сам учебный контент уже включён в архив, а твои результаты нужно перенести:

1. На прежнем сайте https://english-step-gleb.shen2006.chatgpt.site открой «Настройки».
2. Дождись сохранения и нажми «Экспорт».
3. Открой сайт на своём домене, войди и открой «Настройки → Импорт».
4. Выбери скачанный JSON и подтверди замену. Дождись отметки «Сохранено в аккаунте».

После этого проверяй результаты именно на новом сайте. Два сайта работают независимо и не синхронизируются друг с другом. Новый учебный контент также добавлен на прежний сайт. Учебный прогресс на двух сайтах хранится раздельно.

## Где сохраняются данные

SQLite-файл внутри контейнера: `/app/data/english-step.sqlite`.

Docker Compose сохраняет папку `/app/data` в отдельном постоянном томе `progress`. В нём хранятся результаты и сессии входа. Пересоздание контейнера и обновление образа не удаляют этот том.

**Не используй `docker compose down -v`, если хочешь сохранить прогресс:** ключ `-v` удаляет тома. Для обычной остановки достаточно `docker compose stop` или `docker compose down` без `-v`.

Одновременно запускай только один контейнер приложения с этой SQLite-базой. Для масштабирования на несколько серверов потребуется другая архитектура базы.

## Резервные копии

Простой способ — регулярно скачивать JSON через «Настройки → Экспорт». Его можно импортировать даже на новый сервер. Такой файл переносит прогресс, но не настройки входа и не сессии.

Полный снимок SQLite без остановки приложения:

```bash
mkdir -p backups
docker compose exec app node scripts/backup.mjs /app/data/backup.sqlite
docker compose cp app:/app/data/backup.sqlite ./backups/english-step.sqlite
```

Каждый запуск этих команд заменяет предыдущую копию с тем же именем; переименовывай копии, если хочешь хранить историю. Храни копии также вне VPS. Для восстановления прогресса проще всего использовать JSON-импорт. Полную SQLite-копию восстанавливай только при остановленном приложении, заменяя файл базы в томе и удаляя старые файлы `-wal`/`-shm`; перед этим сохрани текущую базу. Файл `.env` сохраняй отдельно: он нужен для входа после переноса.

## Обновление кода

Сохрани `.env`, постоянный том и резервную копию. Замени исходники новыми файлами, затем:

```bash
docker compose up -d --build
```

При обычном обновлении не удаляй `.env` и не создавай новые тома. Не меняй имя папки проекта без сохранения имени Compose-проекта: оно влияет на имя тома. Если всё же переносишь папку, используй прежнее имя через `docker compose -p ПРЕЖНЕЕ_ИМЯ ...` или перенеси базу.

## Сменить или восстановить пароль

Доступ к серверу позволяет создать новый пароль:

```bash
docker run --rm -it --user "$(id -u):$(id -g)" -v "$PWD:/app" -w /app node:24-alpine node scripts/configure.mjs --reset-password
docker compose up -d --force-recreate app
```

Сохрани новый пароль. После перезапуска старые сессии отзываются; на устройствах нужно войти заново. Прогресс остаётся на месте. Восстановление по электронной почте не требуется и не реализовано.

## Если используешь готовую Docker-платформу

В панели платформы:

- Используй приложенный `Dockerfile`; команда запуска уже задана.
- Внутренний порт: `3000` (или значение, которое платформа задаёт через `PORT`).
- Health check: `GET /healthz`.
- Укажи `PUBLIC_URL=https://твой-домен`, `ADMIN_LOGIN` и `ADMIN_PASSWORD_HASH` из созданного `.env`.
- Укажи `DATA_DIR=/app/data` и подключи постоянный диск к `/app/data`. Диск должен быть доступен на запись пользователю контейнера UID 1000.
- Запускай одну реплику приложения. Публичный HTTPS настраивается платформой; Caddy тогда не нужен.

Если платформа не предоставляет постоянный диск, SQLite потеряется при пересоздании контейнера. Для такого сервиса сначала нужно адаптировать приложение под внешнюю БД.

## Если на VPS уже есть Nginx или Caddy

Не запускай второй Caddy на занятых 80/443. Запусти только `app` с публикацией порта на loopback через приложенный файл:

```bash
docker compose -f compose.app.yaml up -d --build
```

Существующий reverse proxy должен направлять запросы домена на `http://127.0.0.1:3000` и обслуживать HTTPS. `PUBLIC_URL` должен совпадать с внешним адресом, а не с внутренним HTTP-адресом контейнера. Сохраняй тот же выбранный compose-файл при дальнейших операциях.

## Запуск без Docker / локальная проверка

Нужен Node.js **24.x**. Зависимостей npm нет.

```bash
node scripts/configure.mjs
npm start
```

Для локальной проверки в настройке укажи `http://localhost:3000`. На внешнем сервере обязательно укажи HTTPS-адрес и поставь reverse proxy. Данные без Docker будут в `./data`, если не изменён `DATA_DIR`. Для постоянной работы без Docker настрой менеджер процессов своего сервера.

## Что проверено

На Node.js 24 проведены реальные HTTP-тесты: вход, защищённые запросы, сохранение SQLite, чтение второй сессией, конфликт версий, повтор запроса, сохранение после перезапуска, выход и отзыв сессий при смене пароля. Логика синхронизации и курс перенесены из проверенной версии сайта.

Docker Engine и браузер в среде подготовки недоступны: сборка контейнера, выдача реального сертификата и внешний вид в браузере здесь не запускались. На сервере проверь `docker compose ps`, вход и отметку сохранения после первого упражнения.

Тесты исходников при установленном Node.js 24:

```bash
npm test
```

## Ограничения и источники

Озвучка использует английские голоса браузера. Проверка свободной речи и произношения автоматически не выполняется. Вход работает по паролю владельца; интеграция с ChatGPT отсутствует. PDF-файлы учебников, изображения страниц и аудиозаписи издателей в архив не включены: использована структура тем, новые упражнения и объяснения созданы для сайта.

Документация используемых компонентов:
- Node.js SQLite: https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html
- Caddy HTTPS: https://caddyserver.com/docs/quick-starts/https
- Caddy reverse proxy: https://caddyserver.com/docs/caddyfile/directives/reverse_proxy
- Docker Engine: https://docs.docker.com/engine/install/

Методика и научные источники доступны внутри сайта в разделе «Как учиться».

## Кино и комиксы

В каждой из 20 тем добавлены два авторских примера по мотивам: кино и комиксный персонаж. Это адаптированные учебные фразы, не дословные цитаты. Есть перевод, объяснение, озвучка и самостоятельная проверка; XP за неё не начисляются.

Раздел «Кино» содержит 24 фильма, фильтр A1–C2, поиск, задания и ссылки на темы курса. Уровни — приблизительная авторская оценка для указанного режима работы, не официальная классификация фильмов. На A1 предлагаются только фрагменты 30–90 секунд.

Контент: `public/media-lessons.json` и `public/film-selection.json`. После замены файлов на уже установленном сервере пересобери приложение командой `docker compose up -d --build`. Сохрани существующий `.env` и том с базой данных; не запускай настройку пароля заново и не удаляй тома. Старые 162 задания сохранили идентификаторы, поэтому прогресс продолжит работать.
